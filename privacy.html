2. Information Server Saver Processes

Server Saver processes information made available through Discord's APIs that is necessary to provide its functionality.

Depending on how the Bot is configured and used, this may include:

Server Information

  • Discord server ID;
  • Server name;
  • Server icon;
  • Server banner;
  • Channel IDs and names;
  • Category information;
  • Role IDs and names;
  • Role hierarchy;
  • Role permissions;
  • @everyone permissions;
  • Permission overwrites;
  • Server configuration, including anti-nuke sensitivity and punishment settings, anti-raid and JoinGate thresholds, backup schedule and retention settings, and the server's customized word-filter list, if any.

This information is required for features such as backups, restoration, anti-nuke, anti-raid, and JoinGate.

User and Member Information

Server Saver may process limited Discord information relating to members, including:

  • Discord user ID;
  • Username or display name;
  • Server roles;
  • Account creation date, where needed to enforce a server's configured JoinGate minimum account age;
  • Whitelist, bot whitelist, and blacklist entries configured for the server;
  • Information necessary to identify the actor responsible for a security or moderation event;
  • Information contained in relevant Discord audit-log events accessible to the Bot.

Security and Moderation Information

Server Saver may record events such as:

  • Bans, kicks, warns, and unbans;
  • Channel and category deletions or creations;
  • Role deletions or creations;
  • Dangerous permission changes;
  • Anti-nuke triggers and the security incidents they are grouped into;
  • Anti-raid join-flood detections and lockdown activity;
  • JoinGate removals (account age or unauthorized bot);
  • Panic Mode activations and deactivations;
  • Backup, export, import, and restore operations, including restore outcomes;
  • Messages removed by the word filter, as described in Section 3;
  • Whitelist, bot whitelist, and blacklist configuration;
  • Other moderation actions.

These records are used to provide Server Saver's moderation, anti-nuke, anti-raid, and recovery functionality, and to generate the security incident reports and dashboard information available to server administrators.

3. Message Content

Server Saver requests Discord's Message Content Intent.

Server Saver's backup and restoration system does not use or store message history.

Server Saver's word filter feature does process message content directly: each message is checked against the server's filtered-word list (a default list, or one an administrator has customized) in order to decide whether to remove it. If a message matches, Server Saver deletes it and posts the removed message's content, author, and channel to the server's configured log channel, so administrators can review what was removed. Server Saver does not otherwise retain message content after this point; filtered message content is not stored in Server Saver's database beyond what is posted to the log channel.

Server administrators should understand that enabling Discord's Message Content Intent makes message content available to the Bot through Discord's API, and that disabling or removing the word filter feature stops this processing.

Server Saver does not use Discord message content to train artificial intelligence or machine-learning models.

If this changes in the future, this Privacy Policy will be updated before such processing is introduced where required by applicable law and Discord policy.

4. Backups

When an administrator uses /backup, or when an automatic scheduled backup runs, Server Saver stores a snapshot of supported server configuration.

A backup may contain:

  • Server name;
  • Server icon;
  • Server banner;
  • Categories;
  • Channels;
  • Roles;
  • Role permissions;
  • @everyone permissions;
  • Permission overwrites;
  • Other configuration necessary for supported restoration functionality.

Server Saver's current storage implementation keeps a configurable number of versioned backups per server, defaulting to five and adjustable by a server administrator up to a maximum of one hundred.

Backups do not contain message history or member-specific permission overwrites because these cannot reliably be recreated by Server Saver.

5. Exported Backups

Administrators can use /exportbackup to generate a JSON backup file.

Exported files are provided to the administrator and may be stored or shared outside Server Saver.

Once an administrator downloads an exported backup, the administrator is responsible for how that file is stored, shared, and protected.

Server Saver cannot control copies of exported files that are stored outside infrastructure under our control.

6. Imported Backups

Administrators may use /importbackup to upload a previously exported JSON backup. Imported files are validated for structure, data types, and size before being accepted; files that do not pass validation are rejected and not stored.

Imported backup information that passes validation is processed so that it can be stored and used by Server Saver's restoration functionality.

Administrators should only upload backups that they are authorized to use.

7. Database Storage

Server Saver stores information required for its operation in a MongoDB database. This is third-party database infrastructure used to host Server Saver's data, rather than a file stored on any single device.

The current implementation stores information including:

  • Server configuration, including anti-nuke, anti-raid, JoinGate, and Panic Mode settings;
  • Administrator whitelist, bot whitelist, and blacklist information;
  • Versioned backups and backup schedule configuration;
  • Anti-nuke trigger history and grouped security incidents;
  • Restore operation history and outcomes;
  • Panic Mode and lockdown history, and the permission state needed to restore a channel's settings after a lockdown ends;
  • A server's customized word-filter list, if one has been configured.

The database is created and maintained as part of the Bot's operation, and access is limited to what Server Saver's own code requires to function.

8. How We Use Information

Information processed by Server Saver is used to:

  • Provide requested Bot functionality;
  • Create, schedule, compare, and restore server backups;
  • Detect potentially destructive or anomalous activity;
  • Execute configured anti-nuke, anti-raid, and JoinGate protections;
  • Apply and report on Panic Mode and lockdown actions;
  • Perform moderation actions, including the word filter;
  • Maintain moderation and security logs and incident reports;
  • Identify actors involved in security events;
  • Maintain administrator whitelist, bot whitelist, and blacklist entries;
  • Provide server status, dashboard, and security self-check information;
  • Diagnose technical problems;
  • Prevent abuse and protect the Service;
  • Comply with applicable legal obligations.

We do not use Discord API data for unrelated purposes.

9. Anti-Nuke Notifications and Logs

When an anti-nuke, anti-raid, or JoinGate event is detected, Server Saver may:

  • Record the event and, where related events occur close together, group them into a single security incident;
  • Post the event in the configured log channel;
  • Take automated protective action;
  • Notify members with Administrator permission through Discord, which may be consolidated into a periodic summary rather than one notification per event during a fast-moving incident;
  • DM the server owner or relevant administrators where supported by the Bot's functionality.

The information contained in these notifications may include information about the detected action and the Discord user responsible for it, where that user could be reliably identified (see Section 7 of our Terms of Service).

11. Data Retention

We retain information only for as long as reasonably necessary to provide Server Saver's stated functionality, maintain security, comply with legal obligations, and resolve disputes.

Backups

The current Server Saver implementation retains a configurable number of versioned backups per server, defaulting to five and adjustable up to one hundred.

Older backups may be removed when the configured retention limit is reached, and only after a new backup has been saved successfully, or when otherwise deleted.

Security Incidents and Anti-Nuke History

Anti-nuke trigger history, grouped security incidents, and restore operation history may be stored as part of the server's security information to support logging, incident review, and the dashboard and safety-check features.

Configuration

Server configuration, whitelist, bot whitelist, blacklist, and word-filter information may be retained while Server Saver is configured for the relevant server.

Specific retention periods may change as the Service develops.

Where Discord or applicable law requires deletion of API data, we will take appropriate steps to delete it unless retention is legally required.
